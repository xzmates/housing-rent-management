# 租赁合同

查询生效租赁合同、新建合同和续租的能力集合。

## 强制执行规则（最高优先级，必须先读）

1. **先调用只读 API，再回答。** 任何涉及房屋、租客、合同、账单、付款、水电、入住退租、经营数据的查询，都必须先调用本技能或关联技能对应的只读接口获取实时数据；**禁止**凭记忆、经验、历史回答或上下文推断直接作答。
2. **本轮查询若无任何工具调用，禁止输出结论。** 用户消息是查询意图时，必须先发起至少一次工具调用，等返回结果后再组织回答；不能直接给答案。
3. **回答事实只来源于工具返回的 `content`。** 只能逐字复述工具返回的金额、日期、数量、对象与状态；工具未返回的内容一律不得编造、推算或补全。
4. **数据不足时**只能回答“当前数据库记录不足以确认”，并列出工具已确认的事实；不得猜测填充。
5. 本规则优先于本文件所有其他说明。违反本规则（未调用工具即作答、编造数据）的回答一律视为错误。

## 触发场景

用户原话举例（路由命中本技能）：

- "查一下有哪些生效的合同"
- "看看现在的租约"
- "哪些房子在出租"
- "给 102 和小问新建合同，月租 1000，押金 1000"
- "东楼北 101 的租约情况"
- "101 提前收三个月租，微信转账已收"
- "101 这个月房租收到了，微信转账"
- "101 从上个月开始一共收四个月"

## 不适用范围

- 房屋查询、租客查询 → 由房屋/租客技能处理
- 退租结算 → 由退租技能处理
- 删除合同 → 回到小程序页面手动操作

## 接口链路

- `getActiveLeases`：查询所有生效中的租赁合同列表；不能回答入住或退租历史。
- `getContractOverview`：有效合同、到期仍有效、同房屋/租客多份有效合同的专用入口。
- `getRelativeLeaseExpiry`：未来 N 天、下个月及最先到期的合同结束日专用入口；合同到期不能改查未来应收账单。
- `listGlobalMoveInOutForRelativePeriod`：查询未指定对象的相对时间入住/退租名单。
- `listGlobalMoveInOutByDateRange`：查询未指定对象的明确日期范围入住/退租名单。
- `getLeaseDetail`：查看单个合同详情（含关联房屋/租客信息）。
- `previewRentCollection`：预览统一租金收款登记并接力到普通页面确认已收款入账。
- `previewPrepayRent`：兼容旧提前收租入口。

## 使用顺序

- 用户查询合同状态时优先展示生效合同列表。
- 用户说“今天/昨天/本周/最近7天/最近30天/这个月/上个月/今年/去年”并询问“入住/退租/搬走”且未点名房屋或租客时，必须调用 `listGlobalMoveInOutForRelativePeriod` 并传 `scope=global_unfiltered`；不得调用 `getActiveLeases`。用户给出某日、某月或明确起止日期时，必须调用 `listGlobalMoveInOutByDateRange`。
- 用户问“有效合同多少/有哪些、有没有到期仍有效、同房屋或同租客多份有效合同”时，必须调用 `getContractOverview`；用户问“最先到期、未来 N 天或下个月哪些合同到期”时，必须调用 `getRelativeLeaseExpiry`；不得调用 `getRelativeFutureReceivables`，后者只回答账单到期。
- `listGlobalMoveInOutForRelativePeriod` 只用于未指定对象的相对时间名单；用户已点名房屋或租客时，严禁从全库活动结果中挑选或推断。用户询问某租客先后住过哪些房、历史合同或签过几份合同时，必须转到 `tenant-skill/getTenantDetailByKeyword`。
- 用户问“欠钱、欠费、没交、没付完、部分付款、逾期、欠多少”时，先识别唯一房屋或租客，再**必须优先**调用 `getArrearsReport`；不得把待缴金额代替欠费明细，也不得将未来应收称为欠费。
- 用户点名租客并问“交过哪些钱、所有付款明细、缴费历史、今年/这个月交过哪些费用、交了多少租金或水电费”时，必须调用 `getTenantPaymentHistoryByKeyword`，传入原始姓名或手机号；该接口先唯一匹配租客，再按 `tenantId` 严格过滤全部关联合同的付款。严禁猜测或复用合同 ID，严禁调用全局日期收款查询补数。用户点名房屋问付款记录时，必须调用 `getHousePaymentHistoryByKeyword`。
- 用户点名租客问“欠多少、欠什么、几笔没付、最早欠款、部分付款、欠费超过 N 天”时，必须调用 `getTenantArrearsByKeyword`；不得先列全量欠费再按名称猜测。
- 用户问“未来 7/10/30 天有哪些费用要收、下周哪些账单到期、未来应收多少”时，必须调用 `getRelativeFutureReceivables`。当前 Agent 不公开可自行生成日期的未来应收入口；用户明确日期范围时不得擅自改用其他查询。不得调用不按日期过滤的收租查询，因为它可能混入已到期欠费或已缴账单。
- 用户问“今天/昨天/某一天/某日期范围实际收了多少钱”时，必须调用 `getFinancialReport` 并传入 `startDate`、`endDate`（单日查询传 `startDate=endDate=当天`），如实报告该区间实际收款流水；严禁用“本月/今年总额”替代单日结果，严禁声称“没有单日接口”。
- 用户问“收了多少钱”时，必须使用“实际收款”口径：只统计真实 `direction=in` 的付款流水，排除 `cashImpact=false` 和 `paymentMethod=deposit_offset` 的内部抵扣。回答时分别说明房租、水电、押金、退租补缴和其他收款。
- 用户问“退了多少钱”时，必须使用“实际退款”口径：按退还押金、退还多收租金、其他退款分别回答。不能将账单金额或合同结算金额直接说成实际退款。
- 用户问“赚了多少钱”时，必须先调用 `getFinancialReport`，再明确说明当前只能统计实际收款、实际退款和退款后净进账；未扣维修、税费等支出，不能等同最终利润。
- `extra_due` 和 `damage` 的实际收款统一称为“退租补缴”。除非付款流水和关联账单能直接证明具体用途，否则不得把退租补缴猜测为房损或水电。
- 用户给出的开始日期晚于结束日期时，必须直接回复日期无效并请用户确认正确日期，严禁自行交换日期后继续查询，也严禁调用任何财务/收款接口；该约束优先于一切补数行为。
- `getSubjectProfile` 仅保留为内部实现，不对 Agent 公开。用户问指定租客资料、当前/历史房屋、合同，使用 `tenant-skill/getTenantDetailByKeyword`；用户问房屋整体档案、房屋押金或房屋实收，必须使用 `house-skill/getHouseProfileByKeyword`。合同约定押金与付款流水实收仍必须严格区分。
- 所有已生成且未结清账单均为“当前待收”；到期日在今天之前的才是其中的“逾期欠费”。没有到期日的账单计入当前待收，但必须说明无法判断是否逾期。
- “未来收租提醒”只来自有效合同的下一收费日，且该期尚未生成未结清租金账单；它是预计提醒，不是欠款，不能与当前待收相加。
- 用户表达租金收款时，先用 `getActiveLeases` 匹配合同，再调用 `previewRentCollection`；不要直接创建账单或收款记录。
- 用户只说金额但没有明确账期时，先追问账期；不要自动换算成提前收租。

## 只读查询边界

- 查询接口只读取 `rentalDomain` 的结构化结果，不得调用任何 `preview*`、`confirm*`、`pay*` 或 `terminate*` 接口。
- 数据库无法证明时必须回答“当前数据库记录不足以确认”，并展示可确认的合同、账单或付款事实。
- 合同结束日不等于实际退租日；实际收入只以 `payments` 流水为准，账单金额和合同押金均不能直接表述为已实收。
- 房损 `damageAmount` 是结算金额，不等于实际到账；只有关联 `payments` 能证明已收款。查询“实际收到多少房损费”时必须使用 `damageReceived`；其证据为 `insufficient` 或 `partial` 时，必须说明当前数据库记录不足以确认全部实际到账。
- 退款结算 `totalRefund` 也不等于实际退款；只有 `refundPaidAmount` 且 `refundEvidence=direct` 才能称为“实际退款”。证据不足时必须说明当前数据库记录不足以确认实际退款。
- 押金是保证金：可以计入“实际收款”的现金进账，但不应表述为房租、水电或利润；押金内部抵扣不属于新增现金。
