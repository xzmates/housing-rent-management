# 租客管理

## 强制执行规则（最高优先级，必须先读）

1. **先调用只读 API，再回答。** 任何涉及房屋、租客、合同、账单、付款、水电、入住退租、经营数据的查询，都必须先调用本技能或关联技能对应的只读接口获取实时数据；**禁止**凭记忆、经验、历史回答或上下文推断直接作答。
2. **本轮查询若无任何工具调用，禁止输出结论。** 用户消息是查询意图时，必须先发起至少一次工具调用，等返回结果后再组织回答；不能直接给答案。
3. **回答事实只来源于工具返回的 `content`。** 只能逐字复述工具返回的金额、日期、数量、对象与状态；工具未返回的内容一律不得编造、推算或补全。
4. **数据不足时**只能回答“当前数据库记录不足以确认”，并列出工具已确认的事实；不得猜测填充。
5. 本规则优先于本文件所有其他说明。违反本规则（未调用工具即作答、编造数据）的回答一律视为错误。

## 只读查询边界

- 查询只读取租客与关联合同，不得触发任何创建或确认操作。
- 同名租客、缺少合同或资料字段时，必须返回候选或说明“当前数据库记录不足以确认”；不得把历史合同、合同押金或账单金额臆测为当前居住、实际收款或实际退还。
- **实际搬离日期只以 `actualMoveOutDate` 为准**。`endDate` 只是合同结束日；当 `actualMoveOutDate` 为空或 `actualMoveOutEvidence` 为 `insufficient` 时，必须回答“当前数据库记录不足以确认准确实际搬离日期”，并可单列合同结束日，绝不能把两者说成同一天。

查询租客列表、查看租客详情和新增租客的能力集合。

## 触发场景

用户原话举例（路由命中本技能）：

- "查一下有哪些租客"
- "看看租客列表"
- "张三的详细信息"
- "新增租客，张三，电话 138..."
- "加个租客，李四"

## 不适用范围

- 房屋查询、合同管理 → 由房屋/合同技能处理
- 删除租客 → 回到小程序页面手动操作

## 接口链路

- `searchTenants`：按关键字和状态搜索租客列表。
- `getTenantDetailByKeyword`：按姓名或手机号安全匹配唯一租客后查看详情（含名下全部合同）。
- `getTenantDetail`：内部详情实现，不作为自然语言 Agent 的可调用入口。

## 使用顺序

- 用户查询租客时优先展示列表。
- 用户选中租客后展示详情。
- 用户问指定租客的“资料、详细信息、手机号、身份证、住哪个房间、合同日期、先后住过哪些房、所有历史合同”时，只能调用 `getTenantDetailByKeyword`，让云端先完成唯一匹配；同名时只能返回候选，绝不能自动选择。不得改用合同技能的综合档案或无对象过滤的全量入住退租名单代替租客详情。
- 新增租客时仅整理姓名、手机号、可选身份证并返回小程序 Handoff；不得直接写入 tenants 或编造敏感资料。
- 用户必须点击卡片进入普通租客页面、核对后手动保存。缺姓名先追问；缺手机号可进入页面补充。

## 查询结果表达

- 调用 `getTenantDetailByKeyword` 成功后，最终自然语言必须复述工具 `content` 中与提问相关的事实；至少包含租客姓名、当前房屋和当前合同日期，问“资料”时还要包含电话、身份证和历史房屋。不得只回答“资料如下”或只显示卡片标题。
- 调用 `searchTenants` 成功后，最终自然语言必须给出工具返回的数量和匹配结果；不得只回答“租客列表如下”。
