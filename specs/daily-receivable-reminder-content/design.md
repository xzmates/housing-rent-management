# 每日当前待收提醒内容优化技术设计

## 设计范围

保持现有模板 ID、模板字段映射、定时任务、订阅额度、幂等发送和首页查询不变。仅修改云函数中的摘要构造、模板字段安全处理及相关测试；跳转版本继续由环境变量控制。

## 现有字段映射

| 业务字段 | 模板字段 | 输出示例 | 约束 |
|---|---|---|---|
| 总待收金额 | `amount28` | `9100` | 有效数字文本 |
| 类型与数量 | `thing18` | `租金｜2项5笔逾期` | 最多 20 字符 |
| 逾期状态 | `phrase17` | `全部逾期` | 最多 5 个汉字 |
| 最早到期日 | `time37` | `2026年5月7日` | 微信日期格式 |
| 重点待收 | `thing9` | `101小笛子6400；204小晶2700` | 最多 20 字符 |

## 摘要算法

### 1. 统计

- `groupCount`：`getCurrentReceivableGroups` 返回的分组数量，即待收项数。
- `billCount`：所有分组 `billCount` 之和，即未结清账单总笔数。
- `overdueCount`：所有分组 `overdueCount` 之和，即逾期账单笔数。
- `totalAmount`：所有分组剩余待收金额之和。
- `earliestDueDate`：所有分组最早到期日的最小值。

逾期状态：

```text
overdueCount == 0                    -> 暂无逾期
0 < overdueCount < billCount         -> 部分逾期
overdueCount == billCount            -> 全部逾期
```

### 2. 账单类型字段

- 单一费用类型：`租金｜2项5笔逾期`。
- 多种费用类型：使用排序第一项的类型并追加“等”，例如 `租金等｜3项5笔逾期`。
- 无逾期时仍明确显示数量，例如 `租金｜2项0笔逾期`。
- 最终通过 20 字符安全限制。

### 3. 排序

复制查询结果后排序，不修改首页返回数据：

1. `overdueAmount > 0` 的分组优先；
2. 同一优先级按 `amount` 从高到低；
3. 金额相同时按房屋标签自然排序，保证结果稳定。

### 4. 备注压缩

单项片段格式为：

```text
房间简称 + 租客简称 + 金额
```

- 房间简称优先取房屋标签中 `-`、`·` 等分隔符之前的房间编号。
- 金额去除无意义的小数尾零，不添加人民币符号和千位分隔符。
- 两项时使用 `第一项；第二项`。
- 超过两项时使用 `第一项；另N项其余金额合计`。
- 先完整保留房间和金额，再按可用字符数缩短姓名；姓名至少保留首个字符。
- 若极端房间编号或金额长度仍导致超限，则进一步压缩房间标签，并以 `textLimit(..., 20)` 作为最终保护。

## 兼容性与风险控制

- 不修改 `getCurrentReceivableGroups`，首页与微信消息继续共享同一业务口径。
- 不修改模板 ID 和字段 key，无需重新获取订阅授权模板。
- 不修改幂等键；同一天已成功发送的消息不会因部署后重跑而重复发送。
- `trial` 消息仅适合体验成员验证；发布流程完成后必须将环境变量切换为 `formal`。
